# Forum

Help threads between a participant and trainers, one thread per `(participantId, itemId)`: `ThreadId` in `forum/dbmodels/thread.ts`. Messages are stored here; thread status lives in AlgoreaBackend and arrives as events. Routes and auth: [api.md](api.md). Storage: [database.md](database.md).

## Subscriptions vs follows

| | Subscription | Follow |
|--|--------------|--------|
| Scope | one WebSocket connection (a browser tab) | a user |
| Purpose | live push of thread activity | notifications for activity missed live |
| Created by | WS `forum.subscribe` (thread token) | REST `POST …/follows`, or automatically when a thread opens |
| Lifetime | WS connection TTL (2 h); deleted on disconnect or a `GoneException` | permanent while the thread is open; 2-week TTL once it closes |

Subscriptions are WS actions, not REST, because only the connection identifies which frontend instance receives the push. On subscribe, the thread ID is stored on the connection (`subscriptionThreadId`) so disconnect can delete the subscription without a scan.

## Posting a message (`POST …/messages`)

Requires `can_write`. Body `{ text, uuid }`, with `uuid` generated by the client. In parallel:

1. Insert the thread event (`sk` = now).
2. Push `forum.message.new` to every subscription; collect the users who received it.
3. Load the followers.

Then notify (`forum.new_message`, [notifications.md](notifications.md)) every follower except the author and the users who received the live push. Returns 201.

`GET …/messages` returns the newest messages first: `limit` query param, default 10, max 20.

## Follows

- `POST …/follows` (thread token): follow; already following is a no-op.
- `DELETE …/follows` (identity token + route params): unfollow; not following is a no-op.
- `GET …/follows` (identity token): `{ isFollowing }`.

## Thread lifecycle (`thread_status_changed`)

A thread is **open** when its status is `waiting_for_participant` or `waiting_for_trainer`.

- Closed → open: remove the TTL from existing follows, then make the participant and `updated_by` followers.
- Open → closed: set a 2-week TTL on every follow, so stale follows expire.

## Other pushes to subscribers

- `submission_created` → `forum.submission.new` `{ answerId, participantId, itemId, attemptId, authorId, time }`
- `grade_saved` → `forum.grade.update` `{ answerId, participantId, itemId, attemptId, score, scoreImproved, validated, time }`

`time` is the event envelope time.
